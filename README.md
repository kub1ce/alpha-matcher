# Alpha Matcher

Alpha Matcher помогает сотруднику сопоставлять банковские операции с договорами, проверять основания решений и разбирать неоднозначные случаи.

В репозитории два самостоятельных приложения. Основной интерфейс «А.Выгодоприобретатель» использует общее демонстрационное состояние. Stage 7 показывает принятый Matching Engine на настоящей локальной MySQL. Экспериментальный движок пока не подключён к бизнес-сервисам основного приложения.

## Возможности приложения

- Реестры и карточки операций, договоров и клиентов, фильтры и пагинация.
- Проверка назначения платежа, предпросмотр предложений автосопоставления и подтверждение допустимых действий.
- Ручной разбор, обоснование решений, изменение и отмена привязок в пределах полномочий.
- Статистика, история запусков, журнал действий, уведомления и обе темы оформления.
- Две демонстрационные роли с проверками разрешений в интерфейсе и сервисах.

Stage 7 отдельно позволяет подготовить синтетический набор или импортировать разрешённый JSON, выполнить сопоставление, посмотреть проверки и кандидатов, сравнить результаты запусков. Предложения движка не сохраняются как подтверждённые привязки.

## Технологический стек

Java 25, Spring Boot 4.1.1, Vaadin Flow 25.3.2 и Maven Wrapper. Основное приложение содержит конфигурацию MySQL и миграции Flyway. Изолированный движок использует JDBC и MySQL Connector/J 9.7.0. Для Windows-запуска Stage 7 нужны Python 3, PowerShell, Node.js/npm и MySQL 8.4.8.

## Архитектура проекта

В основном приложении Vaadin Views используют общие UI-компоненты и demo-сервисы. Сервисы работают с единым состоянием, проверяют разрешения и сохраняют исполнителей решений. Вкладки синхронизируются через Vaadin Push.

Модуль `experiments/matching-engine` имеет собственный Maven-проект без Spring/Vaadin. Принятая версия - `stage6-accepted-1ebb240ff4bc`. Stage 7 подключает движок как зависимость и отдельно реализует UI, импорт, хранение результатов и управление собственным стендом. Fingerprints контролируют неизменность принятого кода и классов.

## Как работает Matching Engine

1. JDBC загружает операцию и участников в согласованном снимке `REPEATABLE_READ`.
2. Парсер извлекает номера договоров, ИНН, ФИО, организации, роли и контекст. Гипотеза нормализации ФИО отдельно подтверждается относительно участника из БД.
3. Репозиторий ищет кандидатов по индексируемым реквизитам и загружает участников с сохранением ролей. Evidence фиксирует ключи, маршрут и полноту поиска.
4. Движок проверяет однозначность, идентичность сторон, противоречия, третьих лиц и полноту анализа.
5. `Decision` содержит статус, предложенный договор для SAFE, кандидатов, признаки и объяснения выполненных проверок.

## Статусы результатов

| Статус | Значение |
|---|---|
| `SAFE` | Доказательств достаточно для безопасного предложения конкретного договора. |
| `REVIEW` | Нужна ручная проверка из-за неоднозначности, противоречий или недостаточных доказательств. |
| `NO_CONTRACT` | Полный поиск по поддерживаемым ключам не обнаружил договор. |
| `TECHNICAL_ERROR` | Stage 7 показывает технический отказ выполнения отдельно от бизнес-решения движка. |
| `SKIPPED` | Движок пропустил уже привязанную операцию либо операцию с неподходящим статусом. |

Статус предложения отличается от статуса обработки операции и от подтверждения привязки сотрудником.

## Безопасность сопоставления

Совпавший номер или ИНН сам по себе не разрешает SAFE. Необходимы согласованные участники и роли, однозначный кандидат и отсутствие блокирующих противоречий. Неполный поиск и исчерпание защитных лимитов не дают SAFE. Выбор первого найденного договора запрещён правилами движка.

Предпросмотр работает без записи привязок. Основной demo-интерфейс повторно проверяет полномочия и актуальность предложений при подтверждении. Его механизм выбора пользователей предназначен для демонстрации и не заменяет производственную аутентификацию.

## Запуск основного приложения

Из корня репозитория в PowerShell с JDK 25 в `JAVA_HOME`:

```powershell
$env:SPRING_PROFILES_ACTIVE = 'demo'
.\mvnw.cmd spring-boot:run
```

Откройте `http://localhost:8080/login`. Выберите роль, заполните логин и пароль. Профиль `demo` отключает MySQL и Flyway, введённые учётные данные не проверяются внешней системой.

Обычный профиль использует `DB_URL`, `DB_USERNAME`, `DB_PASSWORD` и включает Flyway. Перед запуском проверьте выбранную БД и миграции. URL по умолчанию указывает на `alpha_matcher_dev`, исходная миграция содержит `alpha_matcher`. См. [описание БД](docs/database/entities.md).

## Запуск Stage 7

Из корня репозитория с JDK 25 в `JAVA_HOME`, Python 3 и Node.js/npm:

```powershell
.\experiments\matching-engine\stage7\start-demo.ps1 -Verify
python -X utf8 -B experiments/matching-engine/stage7/demo_runtime.py status
```

Launcher создаёт runtime-каталоги, при отсутствии accepted JAR восстанавливает его штатной сборкой и проверяет fingerprints всех 108 accepted classes. Для MySQL 8.4.8 используется `STAGE7_MYSQL_HOME`, подходящая установка в PATH либо автоматическая загрузка официального Windows ZIP Oracle по HTTPS с закреплённым SHA256. Автоматическая установка хранится в `stage7/runtime/dependencies/`. Системные службы и PATH не изменяются.

`STAGE7_MYSQL_HOME` необязателен. Он позволяет явно указать каталог существующей MySQL 8.4.8, содержащий `bin/mysqld.exe`. При неверной версии или неполной установке запуск сообщит об ошибке.

Первое восстановление accepted JAR включает его unit-тесты. Ключ `-Verify` дополнительно запускает стандартные тесты Stage 7 на собственном MySQL. Большие проверки отдельно не включаются. Maven/npm скачивают зависимости при необходимости. После состояния `READY` интерфейс доступен на `http://localhost:8087`. До первого запуска `status` и `stop` возвращают `NOT_STARTED`.

Launcher создаёт отдельный datadir, случайные локальные пароли и каталог `matching_engine_exp` на порту `33357`. Порты `8087` и `33357` должны быть свободны. Стенд ограничен по времени работы и рассчитан на одного локального демонстратора. Повторный запуск возвращает уже работающий собственный экземпляр.

Штатная остановка:

```powershell
.\experiments\matching-engine\stage7\stop-demo.ps1
```

Локальные результаты и datadir находятся в `stage7/runtime/` и не версионируются. Для штатно завершённых наборов действует политика хранения из [инструкции Stage 7](experiments/matching-engine/stage7/README.md). Не импортируйте секреты или персональные данные без разрешения.

## Тесты

Unit-тесты основного приложения и движка из корня репозитория:

```powershell
.\mvnw.cmd -q test
.\mvnw.cmd -q -f experiments/matching-engine/pom.xml test
```

Проверка Stage 7 вместе с запуском собственного MySQL-стенда:

```powershell
.\experiments\matching-engine\stage7\start-demo.ps1 -Verify
```

Дополнительные JDBC integration tests движка запускаются через `Run-MySqlTests.ps1` и требуют PowerShell 7 и Docker с Linux Engine. Скрипт создаёт отдельную временную БД. Большие испытания не входят в обычный запуск Stage 7.

## Ограничения и развитие

Проверки качества основаны преимущественно на синтетических корпусах. Отсутствие ошибочных SAFE на них не доказывает отсутствие ошибок на реальных банковских данных. Распознавание имён, договорных конструкций и третьих лиц ограничено реализованной грамматикой; неопределённые случаи остаются на ручную проверку.

Проверка ИНН подтверждает формат и контрольные цифры, внешние реестры не вызываются. Stage 7 не реализует производственную авторизацию и сохранение подтверждённых банковских привязок. Интеграция требует отдельного проектирования аутентификации, загрузки реальных данных, конкурентного применения решений и эксплуатационных проверок.
