# Alpha Matcher

Alpha Matcher сопоставляет банковские операции с договорами. Сотрудник может проверить реквизиты, причины решения и кандидатов, применить выбранные предложения или передать спорную операцию на ручной разбор. Система ведёт историю заданий, привязок и корректировок.

## Архитектура

Приложение использует Java 25, Spring Boot 4.1.1, Vaadin Flow 25.3.2, MySQL Connector/J 9.7.0 и Flyway 12.4.0. Maven Wrapper 3.3.2 запускает Maven 3.9.12. Для локальных JDBC-проверок используется MySQL 8.4.8.

- В `src/main/java/ru/urfu/alphamatcher/ui/` находятся Vaadin-маршруты и представления. Прикладные сервисы и модель демонстрационных ролей находятся в `demo/`.
- В `matching/` находятся JDBC-чтение операций, поиск и загрузка кандидатов, индексы и долговременные задания. Предпросмотр хранится отдельно от связей. Применение проверяет полномочия и актуальность данных, записывает связи, аудит и прогресс транзакционными пакетами и позволяет восстановить работу после перезапуска.
- `PurposeParser` выделяет реквизиты и контекст назначения платежа. Matching Engine оценивает согласованность участников, ролей и договора, полноту поиска и наличие конфликтов.
- Корневое приложение использует закреплённый `matching-engine-optimized:1.2.5-m68-br` из `vendor/maven/`. Исходный Maven-модуль движка находится в `experiments/matching-engine-optimized/`. Его сборка предназначена для разработки и тестирования движка. Версия в его POM и бинарный артефакт приложения управляются отдельно. [Закреплённая зависимость](vendor/maven/README.md)

`SAFE` требует достаточных доказательств для единственного договора. Совпадения только по ИНН или номеру недостаточно. Конфликт, неоднозначность или неполный поиск требуют ручного разбора (`REVIEW`). `NO_CONTRACT` требует полного поиска, подтвердившего отсутствие подходящего договора. `SKIPPED` означает пропуск по правилам обработки. Технический отказ учитывается отдельно от финансового решения. Роль «Принимающий решения» имеет дополнительные права на сложный ручной разбор, корректировку привязок и аудит.

## Окружение и сборка

Установите JDK 25, настройте `JAVA_HOME` и проверьте `java -version`. Первый запуск Wrapper требует доступа к Maven-репозиториям и источникам frontend-зависимостей Vaadin. Закреплённый JAR движка, его POM и контрольные суммы входят в исходный проект.

Из корня проекта:

```powershell
.\mvnw.cmd -DskipTests package
```

В Unix используйте `./mvnw`. Сборка создаёт `target/alpha-matcher-1.0-SNAPSHOT.jar`.

## Локальная DEMO

В Windows запустите:

```powershell
.\tools\dev\demo.ps1
```

В Unix:

```sh
./mvnw -Dspring-boot.run.profiles=demo '-Dspring-boot.run.arguments=--server.address=127.0.0.1 --server.port=8080' spring-boot:run
```

Откройте `http://127.0.0.1:8080/login`. Профиль `demo` отключает JDBC/Flyway и инициализирует встроенные фикстуры в памяти. Остановите запуск через Ctrl+C. Для DEMO используются только синтетические данные.

## MySQL и Flyway

- **Схема приложения.** Администратор создаёт пустой каталог `alpha_matcher`. Перед запуском без активного DEMO-профиля задайте `DB_URL`, `DB_USERNAME` и `DB_PASSWORD` для выделенной локальной БД. Flyway применяет V1-V7, а проверка каталога перед миграцией требует имя `alpha_matcher`. Существующую историю и checksum миграций сохраняют. Запустите `.\mvnw.cmd spring-boot:run` без активного профиля, чтобы создать DataSource и применить миграции Flyway. Интерфейс подключается к JDBC только в профиле `jdbc-demo`. [Правила Flyway](docs/database/flyway-schema.md)
- **JDBC DEMO и тесты.** В Windows установите Python 3 и распакуйте MySQL 8.4.8 в `tools/runtime-dependencies/mysql-8.4.8-winx64/`. Затем выполните `python -X utf8 -B tools/dev/jdbc.py demo` и откройте `http://127.0.0.1:8088/login`. Сценарий создаёт отдельный datadir с тестовой оснасткой, генерирует временные учётные данные и использует локальный порт 33368. Для Flyway smoke используется 33369. Существующий сервер MySQL должен быть остановлен самим владельцем до запуска JDBC-режимов, если мешает проверке доступности. Скрипты ожидают минимум 41 ГиБ свободного места для JDBC-режимов или 40 ГиБ для Flyway smoke. Действующий локальный datadir владельца не нужен. [Инструменты локальной MySQL](tools/alpha_runtime/README.md)

## Тестирование

```powershell
.\mvnw.cmd test
.\mvnw.cmd -f experiments/matching-engine-optimized/pom.xml test
python -X utf8 -B tools/dev/jdbc.py flyway-smoke
python -X utf8 -B tools/dev/jdbc.py app-it
python -X utf8 -B tools/dev/jdbc.py bulk-it
python -X utf8 -B tools/dev/jdbc.py correction-it
python -X utf8 -B tools/dev/jdbc.py engine-it
```

Первые две команды запускают штатные наборы. JDBC-тесты приложения включаются отдельными переменными окружения. Сценарии `tools/dev/jdbc.py` задают их только для созданной ими БД. Дополнительные сценарии, рассчитанные на специальное сохранённое состояние ручной очереди или исторический стенд, выполняются отдельно на изолированных данных. Запуск тестов с реальными банковскими данными или на постоянной demo-БД запрещён.

Фикстура ИНН физлица `000012345627` используется в примерах проверки парсинга и в регрессиях. Первые десять цифр `0000123456` заданы искусственно с префиксом `00` вместо кода регионального управления ФНС. Последние две цифры `27` вычислены по двум 12-значным контрольным формулам. Фикстура проверяет формат и контрольную сумму парсера. [Описание структуры ИНН ФНС](https://www.nalog.gov.ru/rn08/news/activities_fts/16591014/)

## Структура и дальнейшая разработка

| Путь | Назначение |
| --- | --- |
| `src/main/`, `src/test/` | Приложение, ресурсы Vaadin, миграции, модульные, UI-компонентные и интеграционные тесты. |
| `vendor/maven/` | Репозиторий закреплённой зависимости Matching Engine. |
| `experiments/matching-engine-optimized/` | Maven-модуль движка и его тесты. Корпуса и исходный baseline нужны для действующих регрессий. |
| `experiments/matching-engine/` | Общие SQL-фикстуры и исходные ресурсы для тестов движка, конфигурация изолированного MySQL и инструмент владения стендом. |
| `tools/dev/`, `tools/alpha_runtime/`, `qa/` | DEMO launcher, изолированная JDBC-оснастка и Flyway smoke. |
| `database/`, `docs/` | Модель БД, эксплуатационные заметки и документация поставки. |

Изменения приложения и движка проверяйте в отдельных ветках разработки. Для финансовых изменений сравнивайте полные решения и доказательства и используйте положительные и отрицательные контрпримеры. При изменении движка готовьте отдельную версию Maven-артефакта с контрольными суммами. Существующие миграции Flyway остаются неизменными.

## Ограничения

Вход демонстрационный и позволяет выбрать роль. Production JDBC-провайдер данных UI отсутствует. Работа с реальными банковскими данными требует отдельной аутентификации, серверной проверки полномочий и эксплуатационной и финансовой приёмки. [Готовность DEMO и production](docs/operations/RELEASE_READINESS.md)
