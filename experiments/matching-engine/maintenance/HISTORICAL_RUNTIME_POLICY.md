# Historical runtime storage policy

Обновлено 2026-11-12. Stage5A/5B завершены. Accepted Stage6 и актуальный Stage7 не используют их исторические datadir и ETW. Источники, протоколы, численные результаты, manifests и исходные verdicts сохраняются.

Причина роста: `cold_stand_clone*.py` и `checkpoint_clone_v1.py` создавали полные копии MySQL для каждого admission/recovery; трассировка одновременно сохраняла ETL, XML/XML.gz и compact JSONL. Цепочки повторных попыток накапливали эти данные. Это исторические инструменты, а не обслуживание актуального Stage7.

- Не запускать старые coordinator/start/resume/clone-команды для обычной сборки или демонстрации. Указатели READY и пути в старых manifests после очистки отражают происхождение данных, а не доступный сервер.
- Основное приложение использует Maven Wrapper и профиль `demo`; accepted engine - `build_accepted.py`; Stage7 - собственные `start-demo.ps1`/`stop-demo.ps1` и runtime. MySQL binaries из Stage4cd сохранены. Не удалять их вместе с историческими datadir.
- Новый тяжёлый эксперимент требует отдельного разрешения, нового owned каталога, сохранённых генераторов/seeds/configuration и исходных frozen gates. Старый datadir для cold clone больше не доступен; восстановление выполняется загрузчиком fixtures/dataset, без изменения исторических manifests.
- До запуска оценить максимальный объём **всех** копий базы и форматов трасс. Не сохранять новую копию каждой неудачной admission-попытки без отдельной необходимости.
- После штатной остановки и проверки итоговых численных сводок удалять только собственные временные datadir и сырые трассы по явно проверенному списку. Сохранить manifests, verdicts (включая INVALID/INCOMPLETE/UNKNOWN), SQL snapshots, summaries, исходники, oracle и уникальные результаты. Автоочистка неизвестных/user-import данных запрещена.
- Не менять принятую логику ради retention. Штатная retention Stage7 остаётся отдельным механизмом; очистка 2026-11-12 её не запускала и существующий Stage7 runtime не удаляла.

Однократная очистка документирована в [журнале](cleanup-20261112/REPORT.md). `delete-approved.ps1` привязан к конкретному plan и отказывается повторяться при наличии журнала. Он не является универсальным инструментом удаления. Новую очистку начинать с нового списка кандидатов и проверки ownership/dependencies.
